# Rust API Reference: `xkbcommon` (v0.8+) & `memmap2`

This reference manual documents the pure-Rust APIs, raw structures, and integration patterns for keyboard input mapping and state management in the `nowayprompt` rewrite. It covers the bindings provided by the `xkbcommon` crate (wrapping `libxkbcommon`) and memory mapping utilities from `memmap2`.

---

## 1. Core Modules and Types

The `xkbcommon::xkb` module provides the safe Rust wrappers for context initialization, keymap parsing, and keyboard state tracking.

### Core Structures

#### `xkbcommon::xkb::Context`
The root configuration object. It manages global state, logging, and include paths for keyboard layouts.
```rust
pub struct Context { /* private fields */ }

impl Context {
    /// Creates a new context with the specified creation flags.
    /// Passes 0 (CONTEXT_NO_FLAGS) for default configuration.
    #[must_use]
    pub fn new(flags: ContextFlags) -> Context;

    /// Gets the list of include paths currently used by this context.
    #[must_use]
    pub fn include_paths(&self) -> ContextIncludePaths<'_>;
}
```

#### `xkbcommon::xkb::Keymap`
An immutable, reference-counted object representing the compiled keyboard layout mapping rules.
```rust
pub struct Keymap { /* private fields */ }

impl Keymap {
    /// Compiles a keymap from a string containing the complete layout rules.
    #[must_use]
    pub fn new_from_string(
        context: &Context,
        string: String,
        format: KeymapFormat,
        flags: KeymapCompileFlags,
    ) -> Option<Keymap>;

    /// Compiles a keymap from a file descriptor mapped into memory.
    ///
    /// # Safety
    /// The file descriptor must be valid and the mapped memory must not be truncated
    /// or modified concurrently by other processes.
    #[cfg(feature = "wayland")]
    pub unsafe fn new_from_fd(
        context: &Context,
        fd: OwnedFd,
        size: usize,
        format: KeymapFormat,
        flags: KeymapCompileFlags,
    ) -> std::io::Result<Option<Keymap>>;

    /// Looks up the index of a modifier by its name.
    /// Returns `xkb::MOD_INVALID` (0xffff_ffff) if the modifier does not exist.
    pub fn mod_get_index<S: Borrow<str> + ?Sized>(&self, name: &S) -> ModIndex;
}
```

#### `xkbcommon::xkb::State`
A mutable state machine that tracks active modifier masks, layout groups, and physical key states.
```rust
pub struct State { /* private fields */ }

impl State {
    /// Creates a new state machine for the given keymap.
    #[must_use]
    pub fn new(keymap: &Keymap) -> State;

    /// Updates the state machine with depressed, latched, and locked modifiers and layouts.
    /// This method is intended for serializing compositor states over wire protocols like Wayland.
    pub fn update_mask(
        &mut self,
        depressed_mods: ModMask,
        latched_mods: ModMask,
        locked_mods: ModMask,
        depressed_layout: LayoutIndex,
        latched_layout: LayoutIndex,
        locked_layout: LayoutIndex,
    ) -> StateComponent;

    /// Retrieves the single keysym generated by a keycode under the current state.
    /// Returns `xkb::keysyms::KEY_NoSymbol` if the key does not map to exactly one keysym.
    #[must_use]
    pub fn key_get_one_sym(&self, key: Keycode) -> Keysym;

    /// Checks if a modifier is active in the state by its name.
    pub fn mod_name_is_active<S: Borrow<str> + ?Sized>(
        &self,
        name: &S,
        type_: StateComponent,
    ) -> bool;

    /// Checks if a modifier is active in the state by its resolved index.
    #[must_use]
    pub fn mod_index_is_active(&self, idx: ModIndex, type_: StateComponent) -> bool;

    /// Retrieves the UTF-8 string generated by a key press.
    ///
    /// # Performance Warning
    /// This method allocates a new heap-allocated `String` on every invocation.
    /// For performance-critical loops where only single characters are needed,
    /// query `Keysym::key_char()` or `State::key_get_utf32()` instead to avoid allocations.
    #[must_use]
    pub fn key_get_utf8(&self, key: Keycode) -> String;

    /// Retrieves the UTF-32 codepoint generated by a key press.
    #[must_use]
    pub fn key_get_utf32(&self, key: Keycode) -> u32;
}
```

### Core Constants

| Constant Name | Type | Value | Description |
| :--- | :--- | :--- | :--- |
| `CONTEXT_NO_FLAGS` | `u32` | `0` | Default flags for `Context::new`. |
| `KEYMAP_FORMAT_TEXT_V1` | `u32` | `1` | Format for standard XKB text keymaps. |
| `KEYMAP_COMPILE_NO_FLAGS` | `u32` | `0` | Default flags for compiling keymaps. |
| `STATE_MODS_DEPRESSED` | `u32` | `1 << 0` | Modifier is physically held down. |
| `STATE_MODS_LATCHED` | `u32` | `1 << 1` | Modifier is latched (active for next key). |
| `STATE_MODS_LOCKED` | `u32` | `1 << 2` | Modifier is locked (active until toggle). |
| `STATE_MODS_EFFECTIVE` | `u32` | `1 << 3` | Effective state (union of depressed, latched, locked). |

## 2. Parsing Keymaps from Wayland File Descriptors

Wayland compositors transmit keymaps via file descriptors (`wl_keyboard.keymap` event). To parse the keymap, the client must map the file descriptor to memory using `memmap2` and compile it with XKB.

### Memory Mapping Implementation

```rust
use memmap2::MmapOptions;
use std::fs::File;
use std::os::unix::io::FromRawFd;
use xkbcommon::xkb::{self, Context, Keymap};

pub fn parse_wayland_keymap(
    context: &Context,
    raw_fd: std::os::unix::io::RawFd,
    size: usize,
) -> Result<Keymap, std::io::Error> {
    // 1. Wrap the raw file descriptor in standard File structure.
    // SAFETY: The raw file descriptor must be valid and the program must assume
    // sole ownership of this descriptor (avoid double close).
    let file = unsafe { File::from_raw_fd(raw_fd) };

    // 2. Memory-map the file using memmap2 builder.
    // SAFETY: Under the Wayland protocol, the compositor guarantees that the mapped memory
    // represents the compiled layout. The map length must match the keymap size.
    let mmap = unsafe {
        MmapOptions::new()
            .len(size)
            .map(&file)?
    };

    // 3. Convert the byte slice to a UTF-8 string slice and strip trailing null-terminators.
    let keymap_bytes = &mmap[..];
    let keymap_str = std::str::from_utf8(keymap_bytes)
        .map_err(|e| std::io::Error::new(std::io::ErrorKind::InvalidData, e))?
        .trim_end_matches('\0');

    // 4. Construct Keymap from String.
    Keymap::new_from_string(
        context,
        keymap_str.to_string(),
        xkb::KEYMAP_FORMAT_TEXT_V1,
        xkb::KEYMAP_COMPILE_NO_FLAGS,
    )
    .ok_or_else(|| std::io::Error::new(
        std::io::ErrorKind::InvalidInput,
        "xkbcommon failed to compile keymap string",
    ))
}
```

### Safety Contract for Memory-Mapped Keymaps

Memory-mapping file descriptors is inherently unsafe due to the lack of strict kernel guarantees on shared-memory consistency. The following safety parameters must be upheld:

1. **Undefined Behavior from `SIGBUS`:** If the compositor or another process calls `ftruncate` or shrinks the mapped shared-memory region while the client is reading it, a page fault occurs. This triggers a `SIGBUS` signal on Unix, causing immediate process termination. Clients should catch or handle `SIGBUS` if they require absolute reliability, or trust the compositor's implementation.
2. **Wayland Protocol Version 7 Requirements (`MAP_PRIVATE`):** Starting from version 7 of the `wl_keyboard` protocol, clients **must** map the keymap with private copy-on-write mappings (`MAP_PRIVATE`). Mapping with `MAP_SHARED` can allow clients to inadvertently modify the compositor's shared memory, which is a sandbox violation and security hazard. `memmap2::MmapOptions::map` uses `MAP_PRIVATE` by default under the hood on unix files, but explicit private mapping is required if using raw ffi.
3. **Invalid UTF-8/Malicious Payloads:** `xkbcommon` expects valid UTF-8/ASCII rules. Malicious or corrupt keymaps sent via the file descriptor must be validated at the boundary. Doing a `std::str::from_utf8` check on the mapped slice prevents panics in Rust code before the layout is handed over to the underlying C library.

## 3. State Management and Modifiers

Once the `Keymap` is loaded, a keyboard state object (`State`) is instantiated to track keyboard states.

### Updating Keyboard State
When the Wayland compositor fires the `wl_keyboard.modifiers` event, the client must synchronize its modifier state:

```rust
// wl_keyboard.modifiers event handler arguments:
// depressed: mask of depressed modifiers
// latched: mask of latched modifiers
// locked: mask of locked modifiers
// group: index of active layout group
state.update_mask(
    depressed,       // depressed modifiers (ModMask)
    latched,         // latched modifiers (ModMask)
    locked,          // locked modifiers (ModMask)
    0,               // depressed layout (always 0 on Wayland clients)
    0,               // latched layout (always 0 on Wayland clients)
    group,           // locked layout / active layout index (LayoutIndex)
);
```

### Querying Modifiers (Control, Shift, Alt, Super)

Querying modifier states on every key event requires looking up either the modifier name or index. 

#### Real Modifier Name Constants

| Modifier Constant | Value | Description |
| :--- | :--- | :--- |
| `xkb::MOD_NAME_SHIFT` | `"Shift"` | Represents the standard Shift modifier. |
| `xkb::MOD_NAME_CTRL` | `"Control"` | Represents the standard Control modifier. |
| `xkb::MOD_NAME_ALT` | `"Mod1"` | Represents the standard Alt modifier. |
| `xkb::MOD_NAME_LOGO` | `"Mod4"` | Represents the standard Super/Logo/Meta modifier. |

#### Method A: Index-Based Query (Recommended for Performance)
Resolving modifier names to indices once at startup avoids string allocations and parsing on each keystroke.

```rust
pub struct KeyboardModifiers {
    ctrl_idx: xkb::ModIndex,
    shift_idx: xkb::ModIndex,
    alt_idx: xkb::ModIndex,
    logo_idx: xkb::ModIndex,
}

impl KeyboardModifiers {
    pub fn resolve(keymap: &Keymap) -> Self {
        Self {
            ctrl_idx: keymap.mod_get_index(xkb::MOD_NAME_CTRL),
            shift_idx: keymap.mod_get_index(xkb::MOD_NAME_SHIFT),
            alt_idx: keymap.mod_get_index(xkb::MOD_NAME_ALT),
            logo_idx: keymap.mod_get_index(xkb::MOD_NAME_LOGO),
        }
    }

    pub fn is_ctrl_active(&self, state: &xkb::State) -> bool {
        self.ctrl_idx != xkb::MOD_INVALID
            && state.mod_index_is_active(self.ctrl_idx, xkb::STATE_MODS_EFFECTIVE)
    }

    pub fn is_shift_active(&self, state: &xkb::State) -> bool {
        self.shift_idx != xkb::MOD_INVALID
            && state.mod_index_is_active(self.shift_idx, xkb::STATE_MODS_EFFECTIVE)
    }

    pub fn is_alt_active(&self, state: &xkb::State) -> bool {
        self.alt_idx != xkb::MOD_INVALID
            && state.mod_index_is_active(self.alt_idx, xkb::STATE_MODS_EFFECTIVE)
    }

    pub fn is_super_active(&self, state: &xkb::State) -> bool {
        self.logo_idx != xkb::MOD_INVALID
            && state.mod_index_is_active(self.logo_idx, xkb::STATE_MODS_EFFECTIVE)
    }
}
```

#### Method B: Name-Based Query (Simpler, slower)
Directly checks if a modifier is active using its string representation.
```rust
let ctrl_active = state.mod_name_is_active(xkb::MOD_NAME_CTRL, xkb::STATE_MODS_EFFECTIVE);
let shift_active = state.mod_name_is_active(xkb::MOD_NAME_SHIFT, xkb::STATE_MODS_EFFECTIVE);
let alt_active = state.mod_name_is_active(xkb::MOD_NAME_ALT, xkb::STATE_MODS_EFFECTIVE);
let super_active = state.mod_name_is_active(xkb::MOD_NAME_LOGO, xkb::STATE_MODS_EFFECTIVE);
```

## 4. Key Event Processing

When a key event is triggered, the client must map the raw keycode to a keysym and extract Unicode symbols.

### Keycode Translation (+8 Offset)

Linux input event codes (evdev) are 0-indexed. X11 and XKB protocols shift keycodes by an offset of **8** to preserve backward compatibility with legacy range definitions.
When receiving a keycode from a Wayland `wl_keyboard.key` event, the value **must be shifted by adding 8** before query:

```rust
use xkbcommon::xkb::Keycode;

// raw_key is the u32 keycode from wl_keyboard::Event::Key
let xkb_keycode = Keycode::new(raw_key + 8);
```

### Retrieving and Comparing Keysyms

A single keysym represents a logical symbol. Query the active state to resolve the keysym:

```rust
use xkbcommon::xkb::keysyms;

let keysym = state.key_get_one_sym(xkb_keycode);

match keysym.raw() {
    keysyms::KEY_Return => {
        println!("Return / Enter key pressed");
    }
    keysyms::KEY_BackSpace => {
        println!("Backspace key pressed");
    }
    keysyms::KEY_Escape => {
        println!("Escape key pressed");
    }
    _ => {
        println!("Other keysym: {:?}", keysym);
    }
}
```

### String and Unicode Extraction (Allocation Benchmarks)

XKB provides multiple functions to extract unicode strings or characters from a key event. Choosing the correct API is vital to prevent needless allocations on hot paths.

```rust
// Method 1: Get UTF-8 String (Allocates)
// This allocates a String on the heap on every call.
let text: String = state.key_get_utf8(xkb_keycode);

// Method 2: Get Option<char> (Zero-Allocation)
// Resolves the character locally without heap allocations.
let ch: Option<char> = keysym.key_char();

// Method 3: Get UTF-32 Code Point (Zero-Allocation)
// Returns the raw Unicode scalar value or 0 if it is not a single character.
let codepoint: u32 = state.key_get_utf32(xkb_keycode);
```

## 5. End-to-End Integration Example

This example demonstrates the complete lifecycle of a Wayland-like keyboard controller in Rust, from memory-mapping a keymap file descriptor to processing key events and querying modifiers.

```rust
use memmap2::MmapOptions;
use std::fs::File;
use std::os::unix::io::FromRawFd;
use xkbcommon::xkb::{self, keysyms, Context, Keymap, Keycode, State};

pub struct KeyboardHandler {
    context: Context,
    keymap: Option<Keymap>,
    state: Option<State>,
    modifiers: Option<KeyboardModifiers>,
}

pub struct KeyboardModifiers {
    ctrl: xkb::ModIndex,
    shift: xkb::ModIndex,
    alt: xkb::ModIndex,
    logo: xkb::ModIndex,
}

impl KeyboardHandler {
    pub fn new() -> Self {
        let context = Context::new(xkb::CONTEXT_NO_FLAGS);
        Self {
            context,
            keymap: None,
            state: None,
            modifiers: None,
        }
    }

    /// Handles wl_keyboard.keymap event.
    pub fn on_keymap(&mut self, raw_fd: std::os::unix::io::RawFd, size: usize) -> Result<(), std::io::Error> {
        // Convert raw file descriptor to File (takes ownership)
        let file = unsafe { File::from_raw_fd(raw_fd) };

        // Memory-map the layout description
        let mmap = unsafe {
            MmapOptions::new()
                .len(size)
                .map(&file)?
        };

        // Convert the mapped bytes to UTF-8
        let keymap_str = std::str::from_utf8(&mmap[..])
            .map_err(|e| std::io::Error::new(std::io::ErrorKind::InvalidData, e))?
            .trim_end_matches('\0');

        // Compile the keymap
        let keymap = Keymap::new_from_string(
            &self.context,
            keymap_str.to_string(),
            xkb::KEYMAP_FORMAT_TEXT_V1,
            xkb::KEYMAP_COMPILE_NO_FLAGS,
        )
        .ok_or_else(|| std::io::Error::new(
            std::io::ErrorKind::InvalidInput,
            "Failed to compile layout string",
        ))?;

        // Initialize state machine and resolve modifiers
        let state = State::new(&keymap);
        let modifiers = KeyboardModifiers {
            ctrl: keymap.mod_get_index(xkb::MOD_NAME_CTRL),
            shift: keymap.mod_get_index(xkb::MOD_NAME_SHIFT),
            alt: keymap.mod_get_index(xkb::MOD_NAME_ALT),
            logo: keymap.mod_get_index(xkb::MOD_NAME_LOGO),
        };

        self.keymap = Some(keymap);
        self.state = Some(state);
        self.modifiers = Some(modifiers);

        Ok(())
    }

    /// Handles wl_keyboard.modifiers event.
    pub fn on_modifiers(&mut self, depressed: u32, latched: u32, locked: u32, group: u32) {
        if let Some(ref mut state) = self.state {
            state.update_mask(depressed, latched, locked, 0, 0, group);
        }
    }

    /// Handles wl_keyboard.key event.
    pub fn on_key(&self, raw_key: u32) {
        let Some(ref state) = self.state else { return };
        let Some(ref modifiers) = self.modifiers else { return };

        // Translate evdev keycode to XKB keycode
        let keycode = Keycode::new(raw_key + 8);

        // Get the logical keysym
        let keysym = state.key_get_one_sym(keycode);

        // Check if modifiers are active
        let ctrl_active = modifiers.ctrl != xkb::MOD_INVALID
            && state.mod_index_is_active(modifiers.ctrl, xkb::STATE_MODS_EFFECTIVE);

        // Process special keys
        match keysym.raw() {
            keysyms::KEY_Escape => {
                println!("Escape pressed!");
            }
            keysyms::KEY_BackSpace => {
                println!("Backspace pressed!");
            }
            keysyms::KEY_Return => {
                println!("Return pressed!");
            }
            _ => {
                // Zero-allocation unicode retrieval
                if let Some(ch) = keysym.key_char() {
                    if ctrl_active {
                        println!("Ctrl+{}", ch);
                    } else {
                        println!("Character pressed: {}", ch);
                    }
                }
            }
        }
    }
}
```
